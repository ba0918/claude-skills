## 1. Directory Layout

Following §1 "Roots" of the shared contract, this adapter separates the **queue proper (the artifacts)** from the **machine-specific control and session files (runtime)** into different trees. The queue proper consists of artifacts under the Artifact Store and can therefore be shared and migrated, whereas the runtime is always machine-specific and is never shared or migrated.

`state_root` = `.agents/artifacts/issues/` (the queue proper = the artifacts)

```
.agents/artifacts/issues/
  issue-status.md                # the derived index (compatible with the create workflow, regenerated by rebuild-index)
  ready/{slug}.md                # claimable
  running/{slug}/
    issue.md                     # the entity
    .claim                       # pid + started_at (for orphan recovery). Co-located; see §Note
  done/{slug}.md
  failed/
    transient/{slug}.md          # retry_count in the frontmatter
    permanent/{slug}.md
  archives/
    YYYY-MM/{slug}.md            # the monthly archive
    {legacy-flat-files}          # originating in the existing close workflow
```

`runtime_root` = `.agents/runtime/polling/` (machine-specific, always gitignored, never migrated)

```
.agents/runtime/polling/
  .STOP                          # the graceful kill file (contract §6.1)
  .STOP.hard                     # the hard kill file (contract §6.1)
  .polling-initialized           # the marker for the first-start policy (contract §10; the creation responsibility is in this section's Note)
  .last_archive_month            # the month boundary cache (contract §9)
  session.json                   # the tick session (contract §6.5, only under --stateless)
```

It coexists with the flat `archives/` layout of the existing `close workflow` (on the premise that a same-name collision cannot arise on the FS).

**The destination-directory invariant:** at the head of a tick (immediately after resolving the roots), the adapter guarantees `ready/`, `running/`, `done/`, `failed/transient/`, `failed/permanent/`, and `archives/` with `mkdir -p`.
Every transition thereafter (`claim` / `release` / `mark_done` / `mark_failed` / Partial Claim Rollback §4 /
orphan rollback §6) may presume the destination directory exists (no individual mkdir immediately before a rename).
Because only some queue directories can survive a crash or a partial initialization, this guarantee is performed every tick.
Only the monthly subdirectory `archives/YYYY-MM/` is created on demand, when the archive runs.

> **Why `.claim` is co-located in state_root:** `.claim` is inseparable from the atomic-rename design of `claim()`
> (`mkdir running/{slug}` → `rename ready/{slug}.md running/{slug}/issue.md` →
> `write running/{slug}/.claim`), and it must sit in the same FS tree as the running/ directory.
> It is therefore a runtime-class file that is nonetheless not moved to runtime_root but placed under the queue proper
> (`running/{slug}/`). In the migration inventory too, it is treated as part of the queue proper.

> **The creation responsibility of `.polling-initialized` (the same convention as the Label adapter):** the adapter creates it automatically **after the first successful tick**.
> A successful tick is defined as "the moment it completes with `halt_reason` being `None` or `"dry_run"`". Once created it is never updated.
> If the user deletes it manually, the next tick again forces `--dry-run` (for deliberate re-confirmation).
>
> **The serialization format of `.claim`:** 2 lines of text, `pid: <int>` and `started_at: <ISO8601>` (in that order, no other fields).
> `pid` is **the pid of the tick's executing entity (the polling process)** (not the pid of the delegated cycle).
> A `.claim` that cannot be parsed is a warn + rollback target in orphan recovery (the safe side).

## 2. Interface Implementation (the FS implementation of contract §3)

| Method | The FS implementation |
|---|---|
| `list_ready(limit)` | Scan `ready/` with `readdir` and return as soon as `limit` entries are found (**early termination is mandatory**; a full scan is forbidden) |
| `claim(slug)` | `mkdir running/{slug}` → `rename ready/{slug}.md running/{slug}/issue.md` → `write running/{slug}/.claim` (pid + started_at). On an intermediate failure, Partial Claim Rollback (§4) |
| `release(slug)` | `rename running/{slug}/issue.md ready/{slug}.md` → `rm running/{slug}/.claim` → `rmdir running/{slug}` |
| `mark_done(slug)` | `rename running/{slug}/issue.md done/{slug}.md` → `rm running/{slug}/.claim` → `rmdir running/{slug}` |
| `mark_failed(slug, kind)` | `rename running/{slug}/issue.md failed/{kind}/{slug}.md` → `rm running/{slug}/.claim` → `rmdir running/{slug}` |
| `retry_count(slug)` | Read the frontmatter `retry_count` (undefined means 0) |
| `increment_retry(slug)` | Add 1 to the frontmatter `retry_count`, write it back, and return the new value |
| `kill_file_path()` | `(abspath(runtime_root/.STOP.hard), abspath(runtime_root/.STOP))` — the return order is the check order (§7) |
| `archive_month_boundary()` | See §5 |
| `rollback_orphans(now)` | See §6 |
| `sanitize_slug(raw)` | See §3 |
| `load_session()` | Read `runtime_root/session.json` + JSON parse. `None` if absent; a parse failure warns, quarantine-renames it to `{basename}.corrupt.{ts}`, and yields `None` (starting a new session) |
| `save_session(session)` | Write to `runtime_root/session.json.tmp.{pid}` → replace atomically with `rename` (contract §6.5) |

## 3. The implementation convention of `sanitize_slug()`

The FS implementation rules for the pure function `sanitize_slug` of shared contract §4:

0. **Precheck (always run before Step 1)**: if the raw input contains a control character (`\x00-\x1f`) or a null byte (`\x00`), reject it immediately with `InvalidSlug`. Rejecting it before Step 1's whitelist replacement normalizes it makes hostile input detectable
1. Replace every character outside the whitelist `[a-zA-Z0-9._-]` with `_`
2. Replace `..` with `__` (preventing path traversal)
3. Reject a leading `.` or `/`, and the empty string (`InvalidSlug`)
4. A length cap of 128 characters (truncate + a hash suffix beyond that)
5. Re-verify with `realpath` that the converted path stays under `realpath(state_root)` (detecting escape via a symbolic link)

> A generalization of the existing `sanitize_repo_slug` of `github-issue`. It is scheduled to be promoted to a pure function under `skills/shared/` in the future.

## 4. Partial Claim Rollback

`claim()` has 3 steps: "`mkdir` → `rename` → `write .claim`". The rollback procedure on an intermediate failure:

| The point of failure | Rollback |
|---|---|
| `mkdir running/{slug}` failed | Do nothing and return `ClaimFailed` |
| `rename` failed | `rmdir` the already-created `running/{slug}`, then `ClaimFailed` |
| Writing `.claim` failed | Move `running/{slug}/issue.md` back to `ready/{slug}.md` → `rmdir` → `ClaimFailed` |

Every branch guarantees that **no orphaned directory is left in `running/`**.

The `.claim` permission follows the SHOULD of shared contract [§6.4](../../shared/references/polling-pattern.md#64-orphan-recovery).

### 4.1 `mark_failed` Retain Policy

The retain policy for cycle output at the moment of promotion to `failed/{kind}/{slug}.md`:

- Standard output / stderr / test logs / stack traces are **not saved** (they are discarded)
- What is saved in the frontmatter is **only structured errors**: `error_kind` (an enum), `retry_count` (int), `run_id` (the UUID of the tick/loop session), `failed_at` (ISO8601)
- Free-text error messages and logs of arbitrary length are not included in the frontmatter or the body (preventing context bloat and PII contamination)
- The ability to trace causes is guaranteed at the granularity of the `error_kind` enum (when the granularity is insufficient, extend the enum rather than escaping into free text)
- A postmortem is expected to correlate against other storage (for example, a temporary file holding the cycle's stdout, or an external log) keyed by `run_id` + `failed_at`

## 5. Month Boundary Archive (O(1))

```
archive_month_boundary():
  cur_month = now.strftime("%Y-%m")
  cached = read(runtime_root/.last_archive_month) # "" if absent (the cache is runtime)
  if cached == cur_month: return 0                # ← O(1) early return
  if cached == "":                                # the first start: past months cannot be identified
    write(runtime_root/.last_archive_month, cur_month)
    return 0                                      # do not move (contract §9. Preventing archives/{empty}/)
  # crossing the boundary: scan done/ and move into archives/{cached}/ (the destination is on the state_root side)
  moved = move_all(state_root/done/*, state_root/archives/{cached}/)
  write(runtime_root/.last_archive_month, cur_month)
  return moved
```

Within the same month, a tick performs **no directory scan at all**.

## 6. Orphan Recovery (contract §6.4)

```
rollback_orphans(now):
  recovered = []
  for slug in listdir(running/):
    claim_file = running/{slug}/.claim
    if not exists(claim_file): continue
    (pid, started_at) = parse(claim_file)
    if is_alive(pid): continue                    # running normally
    # a dead pid: roll back (the existence of ready/ is already guaranteed at the head of the tick by §1's destination-directory invariant)
    rename(running/{slug}/issue.md, ready/{slug}.md)
    rm(claim_file); rmdir(running/{slug})
    recovered.append(slug)
  return recovered
```

`is_alive(pid)` is the equivalent of `kill(pid, 0)` (no error = alive, `ESRCH` = dead, `EPERM` = treated as alive, the fail-safe). `started_at` is for the audit log (extensible to a future timeout-based recovery).

## 7. Kill File Path

```
kill_file_path():
  root = realpath(runtime_root)                   # independent of cwd. The control files are on the runtime_root side
  # the return order = the check order (.STOP.hard first, graceful .STOP second)
  return (f"{root}/.STOP.hard", f"{root}/.STOP")
```

**Always resolve to an absolute path.** A relative path is forbidden (a change of cwd becomes a cause of missed detection). `runtime_root` is
`.agents/runtime/polling/` (§1, a different tree from the queue proper's `state_root`).

**The contract on the return order**: the tuple's `[0]` is `.STOP.hard` (the hard kill, the highest priority) and `[1]` is `.STOP` (graceful, second). The caller checks existence in the order `[0]` → `[1]` and halts the moment either exists. **Keep the return order and the check order identical** (previously the return order was `(.STOP, .STOP.hard)` while the check order was `.STOP.hard → .STOP`, an inversion that risked a missed hard-kill detection through misreading).
