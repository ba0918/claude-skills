# Compare Script Requirements

The requirements the compare script (`.design/mockup-diff/compare.mjs`) generated by the LLM in Phase 0: SETUP must satisfy.

## Mandatory requirements

### 1. Runtime and dependencies

- **Node.js ESM** (`#!/usr/bin/env node` + the `.mjs` extension)
- Use **Playwright** (`chromium` only) to take the screenshots
- Resolve Playwright from the target project's `node_modules`
  - Resolve it dynamically with `import { createRequire } from "module"`, so the project's Playwright is used no matter where the script is run from
  - **When the project has no Playwright, exit with a clear error message**

### 2. CLI interface

Mandatory flags:

| Flag | Description |
|--------|------|
| `--config` | the path to `.design/mockup-diff/config.json` (default: `<project-root>/.design/mockup-diff/config.json`) |

Optional flags:

| Flag | Description | Default |
|--------|------|-----------|
| `--pages` | comma-separated page names (overrides pages in config.json) | the config.json value |
| `--viewport` | `widthxheight` | the config.json value |
| `--output` | the screenshot output directory | the config.json value |
| `--port` | the dev server port number (overrides devServer.port in config.json) | the config.json value |
| `--help` | show the help | — |

### 3. Taking the screenshots

#### The mockup side

1. Open the mockup HTML with the `file://` protocol
2. Wait for `document.fonts.ready`
3. When there is page switching, follow `mockup.navigation` in config.json
4. Save each page's screenshot to `{output}/mockup-{page}.png`

#### The app side

1. Start the dev server with `devServer.command` from config.json
2. Wait for startup with a **port connectivity check** (`fetch` retries, up to 30 seconds)
   - stdout detection via `devServer.readyPattern` is used as a **fallback**
   - On timeout, exit with a clear error message
3. Inject the API mock according to `apiMock` in config.json
4. Navigate between pages according to `app.navigation` in config.json
5. Wait for the content to finish rendering according to `app.waitStrategy` in config.json
6. Save each page's screenshot to `{output}/app-{page}.png`

### 4. Generating the comparison HTML

- Generate HTML at `{output}/comparison.html` placing the mockup and app screenshots side by side
- Display them left and right for each page
- The CSS is self-contained inline (no external dependencies)

### 5. Error handling

Exit non-zero with a **clear error message** in all of the following cases:

| Case | Example message |
|--------|-------------|
| config.json not found | `ERROR: Config not found: {path}. Run mockup-diff setup first.` |
| Playwright not installed | `ERROR: Playwright not found in {project}/node_modules. Run: npx playwright install chromium` |
| the mockup file does not exist | `ERROR: Mockup file not found: {path}` |
| the dev server timed out on startup | `ERROR: Dev server failed to start within 30s on port {port}` |
| the dev server port is in use | `ERROR: Port {port} already in use` |
| taking a screenshot failed | `ERROR: Failed to capture screenshot for page '{page}': {reason}` |

### 6. Cleanup

- Clean up the following on **both normal and abnormal termination**:
  - stop the dev server process it started with `SIGTERM`
  - close the Playwright browser instance
- Handle signals with `process.on("SIGINT")` / `process.on("SIGTERM")`

### 7. Output structure

```
{output}/
├── mockup-{page1}.png    # the mockup screenshots
├── mockup-{page2}.png
├── app-{page1}.png       # the app screenshots
├── app-{page2}.png
└── comparison.html       # the side-by-side comparison HTML
```

## API mock injection patterns

Guidelines for the injection method matching `apiMock.type` in config.json:

### `tauri-invoke`

```javascript
await page.addInitScript((mockData) => {
  let callbackId = 0;
  window.__TAURI_INTERNALS__ = {
    invoke: (cmd, args) => {
      if (cmd === "plugin:event|listen") return Promise.resolve(callbackId++);
      if (cmd === "plugin:event|unlisten") return Promise.resolve();
      if (cmd in mockData) return Promise.resolve(mockData[cmd]);
      console.warn(`[tauri-mock] unhandled: ${cmd}`, args);
      return Promise.resolve(null);
    },
    transformCallback: (cb) => { const id = callbackId++; return id; },
    convertFileSrc: (p) => p,
  };
}, mockData);
```

### `fetch-intercept`

```javascript
await page.route("**/api/**", (route) => {
  const url = new URL(route.request().url());
  const endpoint = url.pathname.replace(/^\/api\//, "");
  if (endpoint in mockData) {
    route.fulfill({ json: mockData[endpoint] });
  } else {
    route.continue();
  }
});
```

### `msw`

When MSW is already installed in the project, use the existing MSW handlers.
The policy is to use the project's MSW setup rather than setting MSW up independently inside the script.

### `none`

No API mock is needed (a static page, SSG, and so on). Inject nothing.

## Security notes

- Never put production API keys, tokens, or personal information into `mock-responses.json`
- The generated script is executed through the user's permission gate via the `Bash` tool
- Because the dev server start command is read from config.json, the user should review the contents of config.json so that no unintended command is executed

## Non-requirements (things not to put in the script)

- Automatic pixel-level diff detection (the diff analysis is done by the LLM reading the images)
- An auto-fix feature (fixes are made by the LLM in Phase 4)
- Report generation (the analysis report is generated by the LLM in Phase 3)
