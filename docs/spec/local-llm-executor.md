# local LLM executor（ローカル LLM をスキル回帰テストの実行役にする経路）

## 前提となる言葉

この文書を読むのに必要な言葉を先に説明する。

- **スキル** — このリポジトリが配っている「エージェント（AI に作業させる仕組み）への手順書」。
- **fixture** — `skills/<名前>/fixtures.json`。スキルの振る舞いを再現テストするための「場面（シナリオ）と合格条件（要件）」を集めたファイル。
- **executor（実行役）** — fixture のシナリオを実際に演じる AI。演じたあと、要件ごとに「満たせた / 満たせなかった」を JSON で自己申告する。
- **re-judge（裏取り）** — executor の自己申告を鵜呑みにせず、呼び出し側が成果物の実物と突き合わせて採点し直す義務。[executor-contract](../../skills/skill-regression/references/executor-contract.md) が課している。
- **text-only backend** — プロンプトの文字列を chat API へ中継するだけの実行役。ツールもファイルアクセスも持たない。ローカル LLM（ollama）ラッパーはこれに当たる。

## 解決する問題

スキルの回帰テストを高性能な商用モデルで実走すると、1 バッチで週次トークン上限の大きな割合を消費する。手元のマシンで動くローカル LLM に同じシナリオを演じさせれば金銭コストはゼロになるが、「安い実行役の自己申告をどこまで信用できるか」という別の問題が生まれる。実測（issue #277）では、ローカル LLM が「6 節の調査レポートを提示した」と自己申告したのに、そのレポート本文がどこにも残っていない事例が観測された。成果物の実物が残らない限り、裏取り義務は構造的に果たせない。

この仕様は、ローカル LLM 経路が**何を約束するか**（リポジトリ所有の契約）と、**何を約束しないか**（開発者個人の環境に属する事柄）の境界を定める。

## リポジトリが所有する契約

実装は `skills/shared/scripts/ollama_executor.sh`。呼び出し規約の正本は
[process-queue.md § Text-only backends](../../skills/skill-regression/references/process-queue.md) にある。

1. **入力**: プロンプトを標準入力で受け取る。環境変数 `OLLAMA_MODEL`（モデル名）と `OUTPUT_FILE`（報告書の書き込み先）は必須。
2. **2 回に分けて呼ぶ**: 1 回目でシナリオが求める成果物そのもの（調査レポート等の本文）を書かせ、`OUTPUT_FILE` と同じディレクトリに `artifact.md` として保存する。2 回目は同じ会話の続きとして要件の自己評価だけをさせ、`OUTPUT_FILE` へ書く。これで自己申告と突き合わせる実物が必ず残り、裏取りが可能になる。
3. **異常を無言で通さない**: 通信エラー、サーバのエラー応答、途中で切れた応答、空の応答は、どちらの呼び出しで起きても失敗として報告し、非ゼロ終了する。とくに 1 回目が失敗したら 2 回目には進まない — 途切れた成果物を自己評価させると「実物と食い違う報告」を自ら作ることになるため。
4. **応答本文をコードとして扱わない**: モデルの応答・プロンプトはシェルや Python のソースコードに文字列展開せず、ファイルと環境変数で受け渡す。応答に紛れた任意のテキストが実行されてしまう経路を作らないため。

この 4 点は fake サーバによる自動テスト（`skills/shared/scripts/test_ollama_executor.py`）で機械検証される。

## 環境が所有する事柄（この仕様は値を持たない）

以下は開発者個人の環境と、実行のたびに作られる設定ファイル（batch ごとの `backends.json`）に属する。リポジトリの文書に値を書くと、環境が変わるたびに文書が古くなるため、**この仕様は境界だけを定め、値を定めない**。

- どのモデルを使うか（モデルタグ、パラメータ規模、量子化）
- サーバの場所（`OLLAMA_HOST`）とタイムアウト・トークン上限の調整
- ollama を常駐させるか手動起動にするか、同時に載せてよいモデルサイズ（メモリ事情）

## この経路を使ってよい範囲

text-only backend はファイルを読めず、作業ディレクトリに成果物を置くこともできない。したがって:

- 使ってよいのは、プロンプトだけで完結し、成果物が「報告文そのもの」であるシナリオ（読み取り専用・レポート型）に限る。
- ファイル編集やコミットを要求するシナリオには使えない。自己申告を突き合わせる実物が原理的に存在しないため、採点してもスキルについて何も分からない。
- 商用モデルの実行結果と比較するときの条件（同一プロンプト・比較可能性の記録）は [process-queue.md § Text-only backends](../../skills/skill-regression/references/process-queue.md) に従う。
