# release（このリポジトリのリリース手続きと、その専任スキル）

## 前提となる言葉

- **スキル** — エージェント（AI に作業させる仕組み）への手順書。このリポジトリは配布用の
  スキル集（`skills/`）を plugin（拡張パッケージ）として外部プロジェクトへ配っている。
- **プロジェクトローカルスキル** — `.claude/skills/` に置く、このリポジトリの中でしか
  読み込まれないスキル。配布物には含まれない。
- **リリーストレイン** — このリポジトリのリリース方式。変更は PR ごとに CHANGELOG の
  `## Unreleased`（未リリース節）へ溜め、リリース時にまとめて版番号へ確定する。
  課題が空になるのを待たず、溜まったら出す。
- **workflow_dispatch** — GitHub Actions のワークフローを手動で起動する仕組み。この
   リポジトリのリリース（`release.yml`）は version を入力に取り、
   CHANGELOG の確定・4 つの manifest の同期・タグ発行までを全自動で行う。
- **機械確認** — リリース時の品質ゲート通過保証。「Unreleased の各エントリが参照する
   PR が merged + 必須 check 済み」を `gh` で機械的に確認する（`semantic_reviewed` の
   人間宣誓は廃止、#308）。PR 参照の無いエントリは `none — 理由` 形式の明示免除を要求する。

## 解決する問題

リリースは毎回「bump して」という口頭依頼で行われ、手順（版番号の決め方・事前確認・
起動・監視）がエージェントの記憶と会話履歴にしか存在しなかった。実測事故（2026-08-09）:
CHANGELOG へ未リリース節を積み忘れたまま PR がマージされ、リリース起動が「確定させる
`## Unreleased` が無い」で安全側停止した。この積み忘れは文書整合チェック（CHANGELOG を
対象外にしている）にもレビューにも引っかからず、リリースの最終防壁だけが検出した。
手順を専任スキルに固定し、この検査を起動前へ前倒しする。

## スキルの位置づけ

- 置き場所は `.claude/skills/release/`。**配布物（skills/・plugin manifest・README の
  スキル一覧・CHANGELOG）には一切載せない** — リリース手順はこのリポジトリ専用であり、
  外部プロジェクトに配る意味がないため。
- この置き場のスキルは Codex など他エージェントからは使えない。これは「Claude 固有の
  定義は作らない」という従来方針に対する、リリース手順限定の明示的な例外である
  （2026-08-09 ユーザー裁定）。
- 配布中の幹の案内（using-workflow）にある「リリースは所有スキルなしの終端作業」という
  記述は配布スキル群についてのものであり、本スキルと矛盾しない（変更しない）。

## 手順（7 段）

1. **未リリース変更の確認** — 直近リリースタグ以降に main へ入った変更を一覧する。
   無ければ「リリースするものがない」と報告して終了する。
2. **CHANGELOG 事前検査** — `## Unreleased` 見出しがちょうど 1 つ存在することを確認する。
   無ければ起動せず停止し、エントリの追記（作業ブランチ + PR 経由）を案内する。
3. **版番号の判定** — トレイン規則で提案する: 挙動が変わらない変更のみ → patch、
   契約・出力・挙動の変更を含む → minor。判断が割れる場合・major が視野に入る場合は
   ユーザーに聞く（major の基準は未定義のため常にユーザー裁定）。
4. **版番号の確定** — 提案と根拠を示し、ユーザーの確認を得る。
5. **起動** — `release.yml` を workflow_dispatch で起動する。品質ゲート通過の保証は
   workflow 内の機械確認（Unreleased → PR → merged + 必須 check 済み）が担い、ここでの
   確認はリリース実行の承認（リリースしてよいか）である。確認が無い限り起動しない。
6. **監視** — 実行を完了まで監視し、成否と発行タグを報告する。
7. **失敗診断** — 失敗時は失敗ログを取得して原因を特定し、復旧手順（例: CHANGELOG
   追記 PR → 再起動）を提示する。復旧作業も通常の作業規律（ブランチ + PR）に従う。

## やらないこと（非目標）

- PR の中での版番号 bump（並走 PR の衝突を招くため、確定はリリース時のみ）
- ユーザー確認なしの起動
- 配布物への変更（本スキルの追加・改訂で plugin 利用者に変化は生じない）
- リリース内容そのものの品質保証（それは幹のレビュー・検証の仕事。本スキルは
  手続きの定型化だけを担う）
